## 1. 游戏概述

### 1.1 一句话描述
系统（或对手）生成一个数字互不重复的秘密序列，玩家每轮提交一个同长度序列，系统只回报两个统计量——**定序数**与**逆序数**——玩家在限定次数内靠集合求交推出完整序列。

### 1.2 玩法定位
| 维度 | 说明 |
|---|---|
| 类型 | 益智 / 序列推理（非棋牌、非对抗性强类型） |
| 人数 | 单人闯关（主）；双人 1v1（次，一人设密码一人猜） |
| 单局时长 | 入门 3~5 分钟，进阶 5~10 分钟 |
| 平台 | H5（复用顶牛子 uni-app 工程），后续可随框架出小程序包 |
| 核心体验 | 候选集合求交、每轮反馈压缩解空间、选择区分度最高的猜想 |
| 与顶牛子关系 | 独立玩法模块，共用网络层/房间层/部署体系，不共用游戏核心 |

### 1.3 与常见猜数字玩法的本质区别
- 1A2B（ Bulls & Cows）反馈的是「位置对 + 数字对」，反馈与玩家猜测的位置强相关；
- 本玩法反馈的是**序列自身结构中的逆序关系统计**，**不含任何位置信息**——「哪个数字放对了位置」这一信息通道被完全关闭；
- 玩家必须借助序列结构（上升/下降关系）反推，推理路径完全不同。

## 2. 核心规则（细化）

### 2.1 秘密序列
| 属性 | 入门 | 进阶 |
|---|---|---|
| 长度 L | 4 | 6 |
| 取值范围 | 1~9 的整数 | 1~9 的整数 |
| 约束 | 数字互不重复 | 数字互不重复 |
| 生成方式 | 服务端随机生成 | 服务端随机生成 / 双人版由设密方提交 |

> 候选空间：入门 P(9,4) = 3024；进阶 P(9,6) = 60480。长度 5（P(9,5)=15120）作为可选中间档，见 §6 关卡表。

### 2.2 猜想提交
- 玩家提交一组长度为 L 的序列，数字取自 1~9，同样**互不重复**；
- 允许提交与历史完全相同的猜想（但服务端反馈相同，无增益，客户端提示「与第 N 次猜想重复」）；
- 一次猜想让不撤销：提交即扣次数。

### 2.3 反馈定义（服务端计算，唯一信息出口）

对密码（或猜想）序列 `a[0..L-1]`，按**序列自身相对位置**统计，与玩家猜测的摆放位置无关：

**定义 1 —— 定序数（ascCount）**
某位置上的数字，若其**右侧存在比它更大的数字**，则该数字计入定序数。

**定义 2 —— 逆序数（descCount）**
某位置上的数字，若其**右侧存在比它更小的数字**，则该数字计入逆序数。

- 末位（a[L-1]）右侧无数字，永不计入两者；
- 同一数字只会计入其中一个：右侧同时存在更大与更小的数字时，**同时计入定序数与逆序数**（两个统计量相互独立，同一元素可同时贡献两处）。

**例 1（规则原文权威演算例）**：密码 `2 7 3 9` → 相邻升序对 (2→7)(3→9)，逆序对 (7,3)。反馈 = **(2, 1)**。
（口径细节与完整裁定见 §2.4/§2.5；其他数值样例的推演以 §2.5 v2 口径为准。）

**取值范围**：定序数 ∈ [0, L-1]（相邻对），逆序数 ∈ [0, C(L,2)]。L=4 时反馈组合约 (4×7)=28 种含命中位数维度更多——**信息量足以支撑推理**，救援提示（§2.8）作为兜底。上线前用求解器全量验证（技术方案 §6）。

### 2.4 判定流程（服务端计算，唯一信息出口）
1. 玩家提交猜想 G；
2. 服务端校验：长度 = L、数字 ∈ 1~9、互不重复（校验失败拒绝，不扣次数）；
3. 构造排名序列 R：G 中每个数字替换为它在密码 S 中的下标；**猜错的数字（不在 S 中）不参与统计**（skip 语义）；
4. 反馈 = (定序数 asc, 逆序数 desc)：
   - **定序数** = R 中**相邻升序对**的个数（R[i+1] > R[i] 的 i 数）；
   - **逆序数** = R 中**逆序对**的个数（经典定义：i < j 且 R[j] < R[i]）；
5. 猜中判定：R 收满 L 位且 asc = L-1 且 desc = 0 ⟺ G 与 S 完全相同（充要）。

### 2.5 口径裁定（v2，2026-11-20 与例 1 对齐后锁定）

规则原文的文字定义与例 1 演算存在矛盾：
- 原文文字：「定序数指……右侧存在比它更大的数字」的**元素个数**——按此口径例 1 中 2 的右侧也有更小的 3，应同时计逆序，得 (3,1)；
- 原文例 1 演算：只把 2、3 计入定序、7 计入逆序，得 **(2,1)**。

**开发基线以例 1 演算为准，锁定 v2 口径**：

> - **定序数** = 序列中**相邻升序对**的个数（seq[i+1] > seq[i] 的 i 数，范围 0..L-1）
> - **逆序数** = **逆序对**个数（i < j 且 seq[j] < seq[i]，经典定义，范围 0..C(L,2)）
> - 对局中：先按 skip 语义构造排名序列 R，再对 R 统计上两数。

**自检**：
- 密码 (2,7,3,9) 自身：相邻升 (2→7)(3→9)=2，逆序对 (7,3)=1 → (2,1) ✓ 与例 1 完全一致；
- 猜中时 R = (0,1,…,L-1)：相邻升 L-1、逆序对 0 → 反馈 (L-1, 0)，为猜中的充要信号；
- 全降序 (9,8,7,6)：(0, 6)。

**本节为全文档最高优先级定义，与 §2.3 及原文文字描述冲突处以本节为准。**

### 2.6 反馈计算伪代码（唯一权威实现，与 M1 代码同步）

```js
// S: 秘密序列, G: 玩家猜想（同长 L；G 数字均取自 1..9 互不重复，可含 S 外数字）
// 口径 v2：asc = 相邻升序对数；desc = 逆序对数；猜错数字不参与统计（skip 语义）
function feedback(S, G) {
  const posOf = new Map()            // 数字 -> 在秘密序列中的下标
  S.forEach((v, i) => posOf.set(v, i))
  const R = []
  for (const v of G) {
    const pos = posOf.get(v)
    if (pos !== undefined) R.push(pos) // skip 语义：猜错数字不进 R
  }
  let asc = 0, desc = 0
  for (let i = 0; i < R.length; i++) {
    if (i < R.length - 1 && R[i + 1] > R[i]) asc += 1   // 相邻升序对
    for (let j = i + 1; j < R.length; j++) {
      if (R[j] < R[i]) desc += 1                        // 逆序对
    }
  }
  const solved = R.length === L && asc === L - 1 && desc === 0
  return { asc, desc, solved }
}
```

- solved ⟺ R 恰为 (0,1,…,L-1) ⟺ 猜想与密码完全一致（充要）；
- **注意**：`(L-1, 0)` 且 R 收满 L 位只在猜中时出现，因此它既是通关信号也是唯一强信号；
- skip 语义下，(asc, desc) 相同但命中位数（R 长度）不同是**不同反馈**（客户端展示需区分「命中 n 位」徽标，求解器分区键亦含命中位数）。

### 2.7 闯关与次数限制

| 难度 | 长度 L | 次数上限 | 预期体验 |
|---|---|---|---|
| 入门 | 4 | 12 次 | 摸索规则，基本必过 |
| 标准 | 4 | 8 次 | 需要有序策略 |
| 挑战 | 5 | 5 次 | 需要区分度意识（可选档） |
| 进阶 | 6 | 8 次 | 大空间推理 |

- 次数用尽未猜中 → 本关失败，可重试（重试重新生成密码，消耗 1 点体力/次数限制见 §5 运营数值）；
- 次数内猜中 → 通关，星级按剩余次数比例计算（§5.3）。

### 2.8 救援提示
- **触发**：连续 **3 次**反馈与上一轮完全相同（(A,D) 逐轮不变）时，客户端出现「求提示」按钮（也可主动点击，但只在连续 3 次相同后免费）；
- **内容**：随机揭露**某一个未确定位置**的取值区间（如「第 3 位 ∈ {2, 5, 8}」，区间大小 3；或更宽松时给「第 3 位 > 5」）；
- **限制**：每关**最多 2 次**；使用后星级上限降为 2 星；
- **目的**：避免反馈熵过低（尤其 L=4 时 (A,D) 只有 16 种值）导致死局。

### 2.9 双人版（1v1 设密猜谜）
- 流程：A 设密（A 自己输入一个合法序列，服务端校验互不重复）→ B 猜 → 限定 8 次内 B 猜中则 B 胜，否则 A 胜；
- **应答约束**：A 全程只能看到 B 的猜想去向服务端、收到与 B 相同的两个数字，**不得额外解释或暗示**（客户端不提供任何私聊通道，双人房不渲染聊天框）；
- 计分：猜中 = 猜方 +2 分 / 设密方 +0；未猜中 = 设密方 +2 / 猜方 +0；平局不存在；
- 防作弊：设密方提交的密码服务端校验后**立即对设密方隐藏**（客户端不再回显），防止设密方根据猜想来回改口（密码一经提交锁定）。

## 5. 运营数值

### 5.1 信息论可行性验证（每关可解性）
反馈空间：asc ∈ [0, L-1] × desc ∈ [0, C(L,2)] × 命中位数 ∈ [0, L]，组合远多于单一统计量。用贪心最大信息增益求解器全量验证（M1 实测，2026-11-20）：

| 长度 | 候选空间 | 全量求解结果 | 对应关卡次数 |
|---|---|---|---|
| L=4 | 3024 | **平均 5.42 次，最坏 8 次，全部可解** | 入门 12 / 标准 8 ✓ |
| L=5 | 15120 | 平均 5.13 次，最坏 8 次，全部可解 | 挑战 5 需提示兜底 |
| L=6 | 60480 | 平均 4.72 次，最坏 8 次，全部可解 | 进阶 8 ✓ |

**结论**：标准 8 次对 L=4 贴最坏值（紧张感），入门 12 次宽裕；L=6 进阶 8 次可解但贴边——救援提示兜底（§2.8）。验证脚本进 CI（技术方案 §5），防关卡数值回归。

### 5.2 星级
- 3 星：未用提示且剩余次数 ≥ 上限的 1/3（如标准 8 次剩余 ≥ 3 次猜中）；
- 2 星：未用提示但剩余次数 < 1/3，或用了提示；
- 1 星：通关（其余情况）。

### 5.3 体力（软约束，P1 可选）
- 每日免费 10 点体力，失败扣 1、通关扣 2；不做充值，每日登录回满。若首期不做体力，则失败不设限（推荐首期不做，纯单机无成本压力）。

### 5.4 成就（P2）
- 「一击必中」（首次第 1 次猜中——只可能密码恰好是强结构序列）、
- 「零提示满星」、
- 「通关全部进阶」。

### 6.1 常规关卡（推荐 20 关）

|---|---|---|---|
| 1~3 | 4 | 12 | 入门，教学关卡（第 1 关带引导浮层） |
| 4~8 | 4 | 10 | 熟悉期 |
| 9~12 | 4 | 8 | 标准 |
| 13~16 | 5 | 8 | 拓展长度 |
| 17~20 | 6 | 8 | 进阶 |
| 21+ | 6 | 6~5 | 挑战（无尽模式，程序生成） |

密码生成策略：前 20 关**从精心设计的密码池随机**（保证覆盖各种结构：全升序、全降序、山形、谷形、随机）；无尽模式纯随机。

### 6.2 高阶变体（P2）
反馈改为单一指标「最长连续升序段长度」（R 中最长的连续递增段含元素个数）。此模式下反馈空间只有 L 种，救援提示必开，定位为「第二模式/高阶关卡」。
